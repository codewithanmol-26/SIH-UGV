# API Reference

Base URL (development): `http://localhost:8000`. Interactive Swagger docs
are auto-generated by FastAPI at `/docs` while the backend is running.

## REST endpoints

All endpoints are under `/api`. Request/response bodies are defined in
`backend/api/schemas.py`.

### `POST /api/navigation/destination`

Set Point B in the local coordinate frame (meters, relative to the UGV's
start position).

```json
// Request
{ "x": 3.5, "y": -1.2 }
// Response
{ "ok": true, "state": "READY" }
```

### `POST /api/navigation/start`

Transitions `READY → AUTONOMOUS`. **Returns `409`** if no destination has
been set, or the current state doesn't allow starting.

### `POST /api/navigation/pause`

`AUTONOMOUS`/`REROUTING → PAUSED`. Stops the motor immediately.

### `POST /api/navigation/resume`

`PAUSED`/`SAFE_STOP → AUTONOMOUS`.

### `POST /api/navigation/stop`

Any active state `→ STOPPED`. Clears the destination and current plan.

### `POST /api/navigation/emergency-stop`

**Overrides every other state.** Always succeeds, always stops the motor
immediately. The only way out is a fresh `initialize()` (i.e. restarting the
backend) in this MVP — see `docs/navigation.md` for why that's deliberate.

### `GET /api/navigation/status`

```json
{
  "state": "AUTONOMOUS",
  "destination": [3.5, -1.2],
  "plan_found": true,
  "waypoints": [[0.0, 0.0], [0.5, 0.1], ...]
}
```

### `GET /api/ugv/position`

Current pose from the localization backend (falls back to the simulator's
own position if no pose has been computed yet).

```json
{
  "x": 1.24, "y": 0.31, "heading_deg": 12.0,
  "localization_confidence": 0.82,
  "localization_status": "ACTIVE"
}
```

### `GET /api/ugv/telemetry`

Everything on the dashboard's TELEMETRY panel — see
`backend/api/schemas.py::TelemetryResponse` for the full field list (X, Y,
heading, velocity, distances travelled/remaining, obstacle count, camera
FPS, inference FPS, AI latency, localization confidence).

### `GET /api/system/status`

Per-module honesty labels (`ACTIVE` / `SIMULATED` / `NOT_IMPLEMENTED`) —
what powers the dashboard's STATUS panel.

### `GET /api/perception/objects`

Current frame's raw detections (class, confidence, bounding box in pixel
coordinates).

### `POST /api/camera/source`

**Returns `501` — deliberately not implemented.** Hot-swapping the live
camera source needs the pipeline to be re-initialized safely, which this
MVP doesn't attempt. Set `UGV_CAMERA_SOURCE` in `.env` and restart instead.

## WebSocket: `/ws/telemetry`

One-way, server → browser, ~150ms interval (`api/websocket.py`). Sending
data to this socket is a no-op — commands always go through the REST
endpoints above, so there's exactly one way to command the UGV and it's
auditable as regular HTTP requests.

```ts
interface TelemetryMessage {
  type: 'telemetry';
  state: NavigationState;
  position: { x: number; y: number; heading_deg: number; localization_confidence: number };
  telemetry: Telemetry;                 // same shape as GET /api/ugv/telemetry
  destination: [number, number] | null;
  route: [number, number][];             // current A* waypoints
  trajectory: [number, number][];        // simulator's travelled path, last 200 points
  obstacles: Obstacle[];
  system_status: SystemModuleStatus;      // same shape as GET /api/system/status
  logs: LogEntry[];                        // last 12 events, newest first
  camera_frame: string | null;              // data:image/jpeg;base64,... with detection + traversability overlay burned in
}
```

The full TypeScript type lives in `frontend/src/types/index.ts` and is
hand-mirrored from `backend/api/websocket.py::_build_payload` — there's no
codegen step, so a field rename on one side has to be made on both.

### Reconnection

`frontend/src/hooks/useTelemetryStream.ts` reconnects automatically with
exponential backoff (1s → 10s cap) if the socket closes — e.g. because the
backend restarted. The dashboard's LINK indicator in the top bar reflects
`connecting` / `open` / `closed`.

## Error format

REST errors follow FastAPI's default shape:

```json
{ "detail": "Cannot start from state ERROR" }
```

with the HTTP status code carrying the meaning (`409` for an invalid state
transition, `501` for a genuinely unimplemented endpoint).
